<objective>
Replace the HCP profile's "must have a linked VoiceLiveInstance" data model with direct, inline voice-mode config fields on `HcpProfile` itself (model deployment, speech-output voice, avatar character/style/enabled, recognition language) -- mirroring the AI Foundry portal's direct config style (VMODE-01, backend half).

Purpose: `agent-config-left-panel.tsx`'s "Voice Live Instance" card (Plan 38-02) needs real backend fields to bind to; today `HcpProfile` has no such columns at all (they were intentionally dropped in migration `z33a_drop_hcp_inline_voice_fields` when the VoiceLiveInstance FK became the sole source, per D-09/D-13). This plan reverses that architecture per the user's 2026-08-04 rescope decision, restores equivalent columns, backfills existing data, and repoints `resolve_voice_config()` -- the single choke point already consumed by both the live voice-session loader and the Foundry-agent-metadata builder -- at the new inline fields.
Output: Migrated `hcp_profiles` table with 6 new columns (backfilled from any currently-linked `VoiceLiveInstance`), updated Pydantic schemas (instance reference no longer mandatory), and `resolve_voice_config()` reading HcpProfile directly.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Admin browser -> `PUT/POST /api/v1/hcp-profiles` | Admin-authenticated (existing `require_role("admin")` dependency, unchanged by this plan) request supplies the new direct voice-mode fields |
| `resolve_voice_config()` output -> Azure Voice Live `connect()` call | Server-trusted config flows into an outbound Azure API call; a bad value here is a functional/availability risk, not a cross-tenant data risk |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-38-01 | Tampering | `HcpProfileUpdate.avatar_character`/`avatar_style` | mitigate | Pre-existing `validate_avatar_style()` call in `_load_connection_config` (untouched by this plan) still runs downstream of `resolve_voice_config()` and falls back to a safe default on any unrecognized character/style -- no new validation gap introduced by moving the source from VoiceLiveInstance to inline columns |
| T-38-02 | Denial of Service | `HcpProfileUpdate.voice_live_model` | mitigate | Pre-existing `if hcp_model.lower() not in VOICE_LIVE_MODELS: ... hcp_model = _default_model` fallback in `_load_connection_config` (untouched) still guards against an unsupported/garbage model string reaching Azure's `connect()` call |
| T-38-03 | Tampering | `voice_live_instance_id` clearable via update | accept | Clearing the FK only removes a now-vestigial display/legacy reference; it can no longer affect session behavior once `resolve_voice_config()` stops reading it, so there is no privilege or data-integrity impact from allowing it to be cleared |
