## Component Inventory & Placement (Phase-Specific Discretion Calls)

> These are the discretion items 36-CONTEXT.md explicitly deferred to UI-SPEC (persona switcher UI form/placement, admin persona management placement, thumbnail approach). Locked here as the design contract.

### 1. Admin persona management — dedicated admin route (not settings.tsx)

**Decision:** New dedicated page `frontend/src/pages/admin/avatar-personas.tsx`, mounted at route `/admin/avatar-personas`, with its own sidebar entry — **not** folded into `settings.tsx`.

**Rationale:** This is a multi-row CRUD catalog with create/edit/delete/default-toggle semantics (Table + Dialog), matching the Phase 11/14 precedent (`hcp-profiles`, `voice-live` management pages) rather than the Phase 34 singleton-config precedent (`settings.tsx`'s "Voice per Language" Card, which edits exactly one row). Cramming a multi-row CRUD table with a create dialog into `settings.tsx` would break that page's existing "one card per singleton concern" layout convention.

**Sidebar entry** (`frontend/src/components/layouts/admin-layout.tsx`): add to the existing `configuration` group's `items` array — this inserts a new `<NavLink>` **inside the already-existing `<nav>` element**, so it does not add a second nav landmark and cannot break `voice-live-proxy.spec.ts:489`'s `getByRole("link", { name: /voice live/i })` assertion (that assertion targets the existing "Voice Live" link by name; adding a sibling link doesn't change its visibility or role).

```ts
{ path: "/admin/avatar-personas", labelKey: "avatarPersonas", icon: Smile }
```
Position: immediately after `voiceLive`, before `metaSkills` (adjacent admin-managed voice/avatar concerns stay grouped). `Smile` (lucide-react) — a distinct, unused-elsewhere icon signaling "persona/character."

### 2. Admin persona form — clone `VlInstanceDialog`'s structure exactly

**Decision:** `frontend/src/components/admin/persona-dialog.tsx`, `sm:max-w-2xl max-h-[90vh] overflow-y-auto` Dialog (exact size class reuse from `vl-instance-dialog.tsx`), with these sections in order:

1. **Identity** — `name` (Input), `enabled` (Switch), `is_default` (Switch, disabled + tooltip when `enabled` is off)
2. **Character & Style** — exact clone of `vl-instance-dialog.tsx`'s filter-tabs (`all`/`photo`/`video`) + 4-column thumbnail grid (`AVATAR_CHARACTERS`, `h-14 w-14` circles, `ring-2 ring-primary` selection state, initials-gradient fallback on image 404)
3. **Voice per Language** — one row per supported locale (zh-CN/en-US/es-ES/es-MX/es-US), each a `Select` of `VOICE_NAME_OPTIONS` (reuse the Phase 34 `admin.json` `voiceMap.*` Card layout/copy pattern from `settings.tsx`, adapted to a per-persona sub-section instead of the singleton config) — empty selection is valid (falls back per D-07's resolution chain, so leave a "(use default)" option at the top of each `Select`)
4. **Greeting** — `Textarea` (2 rows), helper caption: *"Spoken by the digital human right after the session connects."*
5. **Persona Prompt Fragment** — `Textarea` (3 rows), helper caption: *"Injected into the system prompt alongside the user's CRM/preference context. Sanitized automatically."*

Footer: `Cancel` (outline) + `Save Persona` (primary, disabled while `name` empty or mutation pending — exact `isSaving` pattern reuse from `vl-instance-dialog.tsx`).

**Table** (`frontend/src/components/admin/persona-table.tsx`): columns — thumbnail (32px), Name, Character/Style, Default (badge, primary-accent colored, only one row shows it), Enabled (Switch, inline-toggleable), Actions (Edit pencil icon button, Delete trash icon button — trash disabled + tooltip *"Set another default first"* on the current default row, mirroring the defaultGuardError copy).

**Delete confirmation:** plain `Dialog` (not `AlertDialog` — none exists in this repo, per the Phase 11 precedent noted in STATE.md decisions).

### 3. User-facing persona switcher — header dropdown, logged-in only

**Decision:** `frontend/src/components/avatar/persona-switcher.tsx`, mounted inside `avatar-page.tsx`'s existing `<header>` (the `h-12` bar at the top, next to the personalization `Badge` + `user.email` block — same conditional branch, `isAuthenticated && user`).

**Form:** `DropdownMenu` (reuse `frontend/src/components/ui/dropdown-menu.tsx` — already used identically in `admin-layout.tsx`'s user-menu). **Not** a Sheet/side-panel and **not** a Dialog:
- A Sheet or Dialog would either visually compete with the existing mobile `Sheet` already used for `SourcesPanel` (risk of two overlapping bottom sheets on small screens) or require a modal overlay for what is a lightweight, single-choice action.
- A `DropdownMenu` renders via a Radix `Portal` with `role="menu"`, not a `<nav>` element — **confirmed safe against the AVUI-01 chrome-absence assertion** (`avatar-clean-ui`/`anonymous-avatar-qa.spec.ts:127`'s `page.locator("nav")).toHaveCount(0)`).

**Trigger:** a compact `Button variant="ghost"` in the header showing the active persona's 32px thumbnail circle + name + `ChevronDown` icon, positioned to the left of the existing personalization `Badge`.

**Content:** header row *"Switch digital human"*, then one row per enabled persona (32px thumbnail + name + style label), with a `Check` icon (primary-accent color) on the currently-active row. Selecting a different row:
1. Closes the menu immediately
2. Fires the `useSetSelectedPersona()` mutation (persists `selected_persona_id` via the existing `UserPreference` upsert)
3. Rebuilds the Voice Live session exactly like the Phase 34 language-switch convention: disconnect + `voiceLive.connect()` re-invocation (same `attemptMicConnect` codepath already in `avatar-page.tsx`), **not** a mid-session hot-swap
4. Shows the `"Switching to {name}…"` toast for the duration of the reconnect; on failure shows the `personaSwitcher.error` toast and leaves the previous persona active (no partial-state UI)

**Visibility for anonymous visitors:** **hidden entirely** (not read-only, not disabled-and-visible). Rationale: anonymous visitors always resolve to the admin-marked default server-side (D-06/D-07) and have no persistence mechanism (no `user_id` row to write to) — showing a switcher they can interact with but whose choice silently evaporates on refresh would be a confusing, un-honest affordance. This is the simpler of the two options 36-CONTEXT.md flagged as open ("read-only or hidden for anonymous") and requires zero extra empty/disabled-state copy.

### 4. Thumbnail approach

**Decision:** static per-character preview images via the existing CDN pattern (`${CDN_BASE}/${characterId}-${style}.png`, from `frontend/src/lib/voice-constants.ts`), with the existing initials-on-gradient fallback (`getAvatarInitials` + `gradientClasses` from `frontend/src/data/avatar-characters.ts`) on image load failure — **exact reuse, zero new assets, no upload UI**. This was already the Claude's-Discretion-recommended approach in 36-CONTEXT.md and matches D-03 (Azure prebuilt characters only).

### 5. LAND-01 — no new UI

Confirmed: LAND-01 is a redirect-target change only (`login.tsx` + `auth-guard.tsx`'s `GuestRoute`). The avatar page (`/`) is already the fully-specified landing surface per the Phase 35 UI-SPEC (AVUI-01) — no new layout, component, or copy is introduced by LAND-01 itself. The only visible-to-user change is that regular users now see the avatar page's existing personalized header state (Badge + email, already spec'd) immediately after login instead of the legacy `/user/dashboard`.

## Interaction State Matrix (PersonaSwitcher)

| State | Trigger appearance | Menu content |
|-------|--------------------|---------------|
| Idle, persona active | Thumbnail + name + chevron, default styling | Full list, active row checked |
| Switching (mutation pending) | Trigger disabled, thumbnail shows a small spinner overlay | Menu closed (already dismissed on selection) |
| Switch failed | Reverts to previous active persona's thumbnail/name | Error toast shown once, no persistent inline error state |
| List loading (initial mount) | Trigger shows a skeleton pill (`Skeleton` component, already in `ui/`) | N/A |
| Only one enabled persona exists | Trigger still renders (shows that persona), menu shows single row, no-op if clicked | Single-row menu, already-checked |

## Out-of-Scope Guardrails (carried from CONTEXT/RESEARCH — binding on planner/executor)

- **No video avatar rendering.** `AvatarView` in `avatar-page.tsx` stays `isDigitalHumanMode={false}`. PERSONA-04's "session uses persona's character/style" is satisfied by storing character+style on the model (admin-facing completeness) and resolving **voice** into the real audio-only session — never by wiring `AvatarConfig`/video into `voice_live_webrtc.py` or `public_avatar.py`.

- **No new i18n whitelist entries.** All new copy in this contract must be genuinely translated into all 5 locales; the 15/15 cap in `untranslated-whitelist.ts` is not touched.
