# Phase 35 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is verification + flag-gating, not new visual design. AVUI-01's UI shape (`avatar-page.tsx` + `SourcesPanel`) already exists and is **locked as-is** by this contract — no re-architecture, no new layout wrappers (per CONTEXT.md D-05). AVUI-02 introduces **zero new visible UI** — it only conditionally removes existing `UserLayout` nav markup behind a flag. Consequently most of this contract's job is to **freeze the existing tokens/copy as the enforced baseline** rather than invent new ones, so the checker and executor have an explicit reference instead of "go look at the code."

## Typography

Declared as the frozen contract for the surfaces this phase touches (`AvatarPage` header, `SourcesPanel`, `UserLayout` nav — no new type roles introduced):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (normal) | 1.5 |
| Label | 14px (`text-sm`) | 600 (semibold) | 1.5 |
| Heading | 20px (`text-xl`) | 600 (semibold) | 1.5 |
| Display | 24px (`text-2xl`) | 600 (semibold) | 1.5 |

Mapping to existing elements (evidence, not new decisions):
- Body → citation `page N` text, empty-state body copy, transcript message text, `text-muted-foreground` helper text
- Label → `AvatarPage` header title span, citation title (`line-clamp-2 text-base font-semibold` — note: citation title actually renders at `text-base`/16px per `sources-panel.tsx:70`; kept as-is, not a Label-role violation since it's the single most prominent line in its own card, functioning as a mini-heading), `Badge` personalization text, nav item active label
- Heading → `SourcesPanel`'s `<h2>` ("Sources" — `text-heading font-semibold`, resolves to the app's default `h2` base style of 20px per `@layer base` in `index.css:263-267`, `text-heading` itself is not a defined Tailwind utility and is a no-op class already present in the codebase — **do not remove it in this phase**, it is out of scope; document only)
- Display → app `h1` (24px/600) — not rendered on the avatar page itself in this phase's scope, listed for completeness/consistency with the rest of the app

Only 2 weights are used across this phase's surfaces: **400 (normal)** and **600 (semibold)**. (The app-wide `--font-weight-medium: 500` exists globally for other pages' `h2`-`h4`/`label`/`button` base styles but is not exercised by any element this phase touches or modifies.)

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`var(--background)`) | Page background, `SourcesPanel` background, header background |
| Secondary (30%) | `#F9FAFB` (`var(--muted)`) / transparent `border-border` (`rgba(0,0,0,0.1)`) | Panel dividers (`border-l`, `border-t`, `border-b` on header), citation card borders, `Sheet` surfaces |
| Accent (10%) | `#1E40AF` (`var(--primary)`) | See explicit reserved-for list below — **the only elements allowed to use primary/accent color on the surfaces this phase touches** |
| Destructive | `#EF4444` (`var(--destructive)`) | Rate-limit / connection-failure toast text only — **never** the "no matching source" empty state (locked rule, see below) |

**Accent (`--primary`) reserved for, on this phase's surfaces:**
1. Floating mobile "Sources" trigger button background (`bg-primary`) — the one primary action to open sources on mobile
2. Personalization `Badge` background/text tint (`bg-primary/10 text-primary`) — signals "you are in personalized mode," not a clickable action
3. Citation card hover border/background tint (`hover:border-primary/40 hover:bg-accent/5`) — affordance that a citation card is a clickable link
4. Active-nav-item underline/text color in `UserLayout` (`text-primary`, active-state underline bar) — unaffected by this phase's flag-gating (the 4 nav items either render with this treatment or don't render at all; no new color state is introduced by hiding them)

**Locked rule (pre-existing, must not regress):** Neither `SourcesPanel` empty state (`empty-pre-question` nor `empty-no-match`) may use `--destructive`/error styling — "no source found" is a normal, expected outcome, not an error (see `sources-panel.tsx` module docstring). Any polish/verification work in this phase that touches `SourcesPanel` must preserve this.

## Copywriting Contract

This phase introduces **no new user-facing strings** for AVUI-02 (nav items are removed from render, not relabeled), and expects **zero or one** new string for AVUI-01 (only the optional D-06 chrome-absence assertion, which is test-only and has no UI copy; D-07's header-title-key question is resolved below). This matters because the shared `untranslated-whitelist.ts` is at its **hard cap of 15/15 entries** — no new whitelist exemptions may be added this phase; any new copy must be genuinely translated across all 5 locales (zh-CN/en-US/es-ES/es-MX/es-US) with key parity, same as every other namespace in this project.

| Element | Copy |
|---------|------|
| Primary CTA (avatar page's core action, unchanged) | "Ask" — existing `avatar:input.sendAriaLabel` key, already translated in all 5 locales; no new CTA is introduced by AVUI-01/AVUI-02 |
| Empty state heading (sources, pre-question) | Existing `avatar:sourcesPanel.emptyPreQuestion.heading` = "No sources yet" (en-US) — locked, do not change |
| Empty state body (sources, pre-question) | Existing `avatar:sourcesPanel.emptyPreQuestion.body` = "Ask the avatar a question and its sources will appear here" — locked |
| Empty state heading (sources, no match) | Existing `avatar:sourcesPanel.emptyNoMatch.heading` = "No matching source this time" — locked, neutral tone (not phrased as an error) |
| Empty state body (sources, no match) | Existing `avatar:sourcesPanel.emptyNoMatch.body` = "Try rephrasing your question" — locked, gives the user a concrete next step |
| Error state | Existing `avatar:toast.rateLimited` = "Too many requests — please wait a moment." (429) and `voice:error.connectionFailed` (voice/mic failures) — locked, no new error copy this phase |
| Destructive confirmation | **None** — this phase has no destructive user action. The AVUI-02 flag toggle is an env-var/Settings value flipped by an operator at deploy time, not a user-facing UI control (per D-02, no admin toggle UI); it requires no confirmation dialog |
| Header title key (D-07 resolution) | **Decision: leave unchanged.** `avatar-page.tsx:257` continues to reuse `avatar:sourcesPanel.title` ("Sources") as the header's leading label. Rationale: no test asserts the literal header string, the reuse is functionally harmless (both header and panel legitimately say "Sources"), and correcting it would require a brand-new i18n key across 5 locales while the whitelist is already at its 15-entry cap — introducing avoidable i18n surface for a cosmetic, non-blocking item contradicts D-05's "verify, don't re-architect" mandate. If the checker or a future phase disagrees, treat as a 1-line key-swap with zero test impact (per RESEARCH.md Open Question 3), not a spec violation to block this phase on. |

## AVUI-02 Interaction Contract (nav-gating, non-visual but locked here to prevent scope drift)

| Aspect | Contract |
|--------|----------|
| Flag name | `feature_legacy_coach_nav_enabled: bool = False` (backend `Settings`) → `legacy_coach_nav_enabled: boolean` (frontend `FeatureFlags`) — **default hidden** |
| Field ordering (Claude's discretion, resolved) | Append as the 6th flag, after the 5 existing `feature_*_enabled` entries, in both `Settings` and the `FeatureFlags` Pydantic/TS model — matches this codebase's existing convention of flags being added in chronological/feature order, not alphabetically re-sorted |
| Gated elements | `UserLayout`'s `navItems` array (dashboard/training/history/reports) — **both** render sites: desktop `<nav>` (line ~85) and mobile `Sheet`'s `<nav>` (line ~156). Both must be gated together in the same commit — gating only one creates a desktop/mobile inconsistency, which is an explicit anti-pattern per RESEARCH.md |
| Un-gated elements (explicitly out of scope, do not touch) | `AdminLayout` sidebar (any of it), `GuestRoute`/`login.tsx` post-login redirect targets, `AvatarPage`'s own header/layout, any backend route/endpoint |
| Visual state when hidden | The 4 `NavLink` items simply do not render — no placeholder, no disabled/greyed state, no "coming soon" copy. `UserLayout`'s logo, right-side controls (theme picker, language switcher, notifications, user avatar dropdown), and mobile hamburger trigger remain untouched and always visible regardless of flag value |
| Chrome-absence assertion selector (Claude's discretion, resolved) | `expect(page.locator("nav")).toHaveCount(0)` on `/` (the `AvatarPage` route) — semantic-element count, not `data-testid`, because `AvatarPage` never renders a `<nav>` element at all (its header is a `span` + `Button`, no nav semantics) so this is a true structural assertion, not an implementation-detail-coupled one. Place in `frontend/e2e/anonymous-avatar-qa.spec.ts` (extend existing spec) rather than a new file, since it strengthens an existing "clean UI" story rather than starting a new one |
