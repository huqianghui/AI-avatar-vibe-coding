This plan also fixes every backend call site that currently reads `persona.greeting` as a raw string, since those break the moment the column is renamed.

Purpose: PERSONA-07 makes greetings locale-correct (D-37-3); HARD-01 makes the exactly-one-default invariant defense-in-depth at the database level, not just the service layer (D-37-5), and is a pure additive migration with zero data loss (D-37-4).
Output: `greeting_map` column + resolution chain, partial unique index, updated schemas/service/API call sites, updated backend test suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin (JWT + role) -> `POST/PUT /admin/avatar-personas` | Trusted but still free-text `greeting_map` values per locale — persisted as-is (greeting is spoken text, not a system-prompt-equivalent field; no sanitization gate applies here, unlike `prompt_fragment`) |
| Anonymous/logged-in client -> `/public/avatar/webrtc/session`, `/users/me/selected-persona` | Untrusted `locale` input, closed 5-value allowlist via regex — no free-text locale ever reaches the resolution chain |
| Any code path bypassing `avatar_persona_service.py` (e.g. a future direct ORM mutation) | The last line of defense is the DB itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-01 | Tampering | `locale` param on `webrtc_session`/`selected-persona` | mitigate | Closed regex allowlist (`^(zh-CN\|en-US\|es-ES\|es-MX\|es-US)$`), already the codebase's established pattern — no free-text locale ever indexes into `greeting_map` |
| T-37-02 | Denial of Service (minor) | Partial unique index `IntegrityError` surfacing a raw 500 if the service-layer guard is ever bypassed | mitigate | `try/except IntegrityError` around `create_persona`/`set_default_persona` commits, translated to `ConflictException` (409), consistent with `backend/app/utils/exceptions.py` conventions |
| T-37-03 | Information Disclosure | Malformed/malicious `greeting_map` JSON crashing resolution | accept | `parse_persona_greeting_map` already falls back to `{}` on parse failure (mirrors `parse_persona_voice_map`'s proven pattern) — worst case is the hardcoded `DEFAULT_GREETING`, never an exception |
</threat_model>
