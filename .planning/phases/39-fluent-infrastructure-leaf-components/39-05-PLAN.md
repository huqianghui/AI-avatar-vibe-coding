<objective>
Migrate Checkbox and Switch (LEAF-04) to be internally backed by Fluent UI, each committed independently (D-07). The defining risk (Pitfall 5) is an event-signature and vocabulary mismatch: Radix's `onCheckedChange(bool | "indeterminate")` versus Fluent's `onChange(ev, data)` where `data.checked` is `bool | "mixed"` -- note the STRING VALUE DIFFERS ("mixed" vs "indeterminate"), a silent naming trap that must be shimmed at the adapter boundary, not left leaking through.

Purpose: this is the first plan in Phase 39 requiring a genuine event-contract translation layer (not just a prop-name/appearance remap like Plans 02-04). Getting the tri-state shim wrong breaks any consumer relying on the literal string `"indeterminate"`.
Output: `checkbox.tsx`, `switch.tsx` each Fluent-backed with unchanged `onCheckedChange` signatures; `checkbox.test.tsx` updated in place (existing file with 2 assertions at lines 20/26 that reference `data-state="checked"/"unchecked"` -- per FEATURES.md's explicit recommendation, the adapter itself re-emits these data-state values manually so those 2 assertions need NOT be rewritten) plus a NEW dedicated tri-state/indeterminate test added; `switch.test.tsx` newly created (no prior test file existed).
</objective>
