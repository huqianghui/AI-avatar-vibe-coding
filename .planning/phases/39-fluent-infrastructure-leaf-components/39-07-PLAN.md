Migrate Avatar (LEAF-06), the final and highest-complexity leaf component in Phase 39, to be internally backed by Fluent UI. Unlike every other leaf component in this phase, Avatar's public API is children-composition-based (`<Avatar><AvatarImage/><AvatarFallback/></Avatar>`, mirroring Radix's sub-component pattern) while Fluent's `Avatar` takes flat props (`name`, `image`, `initials`, `icon`) -- this requires an internal `React.Children.forEach` parse step, and a manually-wired `onError` handler for the broken-image-falls-back-to-initials behavior, since jsdom does not naturally fire `error` events on `<img>` elements in tests (Pitfall 21).

Adapter parsing strategy: inside the new `Avatar` wrapper component, use `React.Children.forEach(children, (child) => { if (!React.isValidElement(child)) return; if (child.type === AvatarImage) { imageSrc = child.props.src; imageAlt = child.props.alt; } if (child.type === AvatarFallback) { fallbackContent = child.props.children; } })` to extract the flat values, then render Fluent's `<Avatar image={imageLoadFailed ? undefined : { src: imageSrc, alt: imageAlt, onError: () => setImageLoadFailed(true) }} initials={typeof fallbackContent === "string" ? fallbackContent : undefined} name={imageAlt} ... />`. `AvatarImage` and `AvatarFallback` themselves become simple marker components (never rendered directly -- their sole purpose is to be recognized by `React.Children.forEach` in the parent; e.g. `function AvatarImage(_props: { src?: string; alt?: string }) { return null; }`), OR real components if any existing consumer renders them standalone outside an `<Avatar>` wrapper (check via read_first before deciding).
