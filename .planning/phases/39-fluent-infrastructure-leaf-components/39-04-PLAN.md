<objective>
Migrate Input, Label, and Textarea (LEAF-03) to be internally backed by Fluent UI, each committed independently (D-07). The defining risk for this trio is Pitfall 20: Fluent wraps the native element in a root `<div>`, shifting the natural ref-forwarding target from the root to the inner native element -- this MUST be fixed explicitly, not left as a silent behavior change, because `avatar-page.tsx` has a real, concrete `.focus()` consumer depending on the ref resolving to the actual `<textarea>`.

Purpose: Input/Textarea are the highest-real-world-usage leaf components with an actual live regression risk (not just theoretical) -- `avatar-page.tsx`'s `handleUseTextInstead` callback calls `textareaRef.current?.focus()`. Label is low-risk (single a11y association prop) and rides along in the same plan since it shares no files and is trivial.
Output: `input.tsx`, `label.tsx`, `textarea.tsx` each Fluent-backed with unchanged export signatures and ref-forwarding fixed to target the real DOM node; new `input.test.tsx`/`label.test.tsx`/`textarea.test.tsx` (no prior test files existed for any of the three); `avatar-page.tsx` verified (not modified unless the ref-fix requires a call-site change, which it should not if the fix is done correctly inside `textarea.tsx`).
</objective>

Fluent `Input`/`Textarea` API (both wrap the native element in a root `<div>` -- this is the crux of Pitfall 20):
```ts
declare const Input: React.ForwardRefExoticComponent<{
  appearance?: "outline" | "underline" | "filled-darker" | "filled-lighter";
  size?: "small" | "medium" | "large";
  contentBefore?: React.ReactNode; contentAfter?: React.ReactNode;
  input?: Partial<React.InputHTMLAttributes<HTMLInputElement> & { ref: React.Ref<HTMLInputElement> }>;
  root?: Partial<{ className: string }>;
  className?: string;
} & Omit<React.InputHTMLAttributes<HTMLInputElement>, "size"> & React.RefAttributes<HTMLInputElement>>;
```
IMPORTANT (verified against Fluent v9 source): Fluent's `Input`/`Textarea` DO forward their `ref` prop to the INNER native element already (Fluent's own `useInput_unstable`/`useTextarea_unstable` hooks target the input slot ref, not the root div slot) -- confirm this behavior explicitly with a unit test rather than assuming from this doc (per Pitfall 20's exact warning: "verify, don't assume ref target"). If verification shows the ref actually resolves to the root div instead, use the `input`/`textarea` slot prop's own `ref` (e.g. `<Input ref={forwardedRef}>` should already work per the public API; if it does not, fall back to `<Input input={{ ref: forwardedRef }}>`).
