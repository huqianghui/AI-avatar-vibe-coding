    Create `backend/app/services/rate_limit.py`:
    ```python
    from fastapi import Request
    from slowapi import Limiter
    from slowapi.util import get_remote_address

    def get_anon_session_key(request: Request) -> str:
        """Rate-limit key derived from the anonymous session token header, falling back
        to remote IP only when the header is absent (e.g. the session-creation route
        itself, which has no session yet)."""
        return request.headers.get("X-Anon-Session", get_remote_address(request))

    limiter_ip = Limiter(key_func=get_remote_address)
    limiter_session = Limiter(key_func=get_anon_session_key)
    ```

    ```python
    @app.exception_handler(RateLimitExceeded)
    async def rate_limit_exceeded_handler(request: Request, exc: RateLimitExceeded):
        response = JSONResponse(
            status_code=429,
            content={"code": "RATE_LIMITED", "message": "Too many requests. Please wait and try again.", "details": {"limit": str(exc.detail)}},
        )
        response.headers["Retry-After"] = "60"
        return response
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Anonymous client → new public endpoints (built in later plans, infra here) | Fully untrusted input; no prior auth boundary exists for this path today |
| Rate-limit key extraction → Limiter | Header value (`X-Anon-Session`) is client-supplied and unverified at this layer — must never be trusted as an identity claim, only as a coarse abuse-throttling bucket key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-32-01 | Denial of Service | `rate_limit.py` key funcs | mitigate | Dual IP+session Limiter instances, proven independent via Wave-0-style smoke test (Task 2) before any real endpoint uses them |
| T-32-02 | Information Disclosure | slowapi default `RateLimitExceeded` handler | mitigate | Custom handler in `main.py` returns the project's `{"code","message","details"}` shape, not slowapi's default plain-text/stack-trace-adjacent response |
| T-32-03 | Repudiation | Anonymous interactions with no audit trail | mitigate | `AvatarInteractionLog` model created now (write-path wired in Plan 32-03), nullable `session_id` with `ondelete="SET NULL"` so audit rows outlive session expiry/cleanup |
| T-32-04 | Tampering | `X-Anon-Session` header spoofed to bypass session-level quota | accept | Session-level quota is a coarse abuse throttle, not an authorization boundary; actual authorization happens later via signed-token verification (Plan 32-02) — a forged header at worst gets its own bucket, it cannot forge a valid session or bypass the IP-level limiter |

</threat_model>
