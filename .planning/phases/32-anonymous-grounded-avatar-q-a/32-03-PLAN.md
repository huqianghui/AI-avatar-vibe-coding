<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Anonymous client → `POST /public/avatar/webrtc/session` | Untrusted; must never issue a credential without a verified, unexpired anonymous session |
| Ephemeral credential → browser WebRTC `RTCPeerConnection` | Short-TTL Azure credential is exposed client-side by design (WebRTC direct connection); TTL is the sole containment control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-32-11 | Denial of Service / Cost Exposure | `webrtc/session` endpoint | mitigate | Dual IP+session rate limiting (`anon_rate_limit_webrtc_ip`/`_session`, config-driven per Pitfall 5), on top of the endpoint requiring a verified anonymous session — a bot must first pay the session-creation rate-limit cost before it can even attempt a webrtc-session request |
| T-32-12 | Elevation of Privilege | `WebrtcSessionRequest` body | mitigate | No `character`/`style`/`voice`/`agent_id` override field exists — avatar identity is 100% server-resolved from `PublicKnowledgeConfig`, only `locale` (enum-constrained) is client-influenced |
| T-32-13 | Information Disclosure | Ephemeral credential leaked via browser devtools/network tab | accept | Inherent to the WebRTC-direct architecture the user explicitly chose (CONTEXT.md: "传输路径：WebRTC 直连"); mitigated only by short TTL, which is already a locked requirement, not something this plan can further reduce |
| T-32-14 | Spoofing | Requesting a webrtc session without ever having created a valid anonymous session | mitigate | `Depends(get_anonymous_session)` runs before `issue_ephemeral_credential` is called — verified by the "no Azure call on invalid token" test asserting the mock was never invoked |

</threat_model>
